# Codex CLI First-Class Support for AIDA

**Date**: 2026-03-17
**Status**: Analysis complete, ready for implementation

## Overview

OpenAI's Codex CLI (`codex-cli` v0.111.0) is an agentic coding tool that operates similarly to Claude Code but with a different ecosystem. AIDA currently has basic Codex support (AGENTS.md generation, mention of `.codex/skills/`), but it's not functional. This document analyzes what's needed for first-class support.

## Codex CLI Architecture

### How It Works

Codex CLI uses:
- **AGENTS.md** — project instructions (equivalent to CLAUDE.md)
- **`~/.codex/config.toml`** — global config with per-project trust levels
- **`~/.codex/rules/`** — default rules for command approval
- **MCP servers** — external tool integration (`codex mcp add/list/remove`)
- **Exec mode** — non-interactive: `codex exec "implement FR-042"`
- **Review mode** — code review: `codex review --base main`
- **Sandbox** — Landlock/Seatbelt sandboxing for command execution

### Key Differences from Claude Code

| Feature | Claude Code | Codex CLI |
|---------|------------|-----------|
| Instructions file | `CLAUDE.md` | `AGENTS.md` |
| Skills location | `.claude/skills/*.md` | No standard skill system |
| Commands | `.claude/commands/*.md` | N/A |
| Hooks | `.claude/settings.json` hooks | `~/.codex/rules/` (prefix rules) |
| MCP config | `.mcp.json` (project-local) | `codex mcp add` (global or per-project) |
| Non-interactive | Not directly | `codex exec "prompt"` |
| Code review | Manual | `codex review --base main` |
| Sandbox | Permission system | Landlock/Seatbelt |

### What Codex CLI Can Do That's Relevant

1. **`codex exec`** — run AIDA workflows non-interactively:
   ```bash
   codex exec "Using AIDA, list all approved requirements and create implementation plans for each"
   ```

2. **MCP integration** — Codex can use AIDA's MCP server:
   ```bash
   codex mcp add aida -- aida mcp-serve
   ```

3. **`codex review`** — code review that could check requirement traceability:
   ```bash
   codex review --base main "Check that all new code has trace comments linking to requirements"
   ```

4. **Resume/fork** — continue or branch from previous sessions (context persistence)

## Current State of AIDA's Codex Support

### What Exists

1. **AGENTS.md generation** (`aida-core/src/scaffolding/codex_md.rs`)
   - Basic project overview + commands reference
   - Lists AIDA skills (but `.codex/skills/` isn't actually scaffolded)
   - Generated by `aida init --agent codex` or `aida init --agent both`

2. **ScaffoldConfig flags** (`scaffolding/mod.rs`)
   - `generate_agents_md: bool`
   - `generate_codex_skills: bool`
   - Both default to `true`

### What's Missing

1. **No `.codex/skills/` directory created** — the flag exists but no templates are scaffolded
2. **MCP server not configured** for Codex — `aida init` sets up `.mcp.json` for Claude Code but doesn't run `codex mcp add`
3. **AGENTS.md is thin** — doesn't include distributed mode, GitHub integration, or new skills
4. **No Codex-specific workflows** — exec mode recipes, review integration
5. **No trust level auto-configuration** — user has to manually trust the project

## Implementation Plan

### Phase 1: MCP Integration (Highest Impact, Lowest Effort)

The single most impactful thing: configure AIDA's MCP server for Codex.

```bash
# During aida init, if codex is detected:
codex mcp add aida -- aida mcp-serve
```

This gives Codex access to all AIDA tools:
- `list_requirements`, `show_requirement`, `add_requirement`
- `update_requirement`, `search_requirements`, `add_comment`
- `list_features`

**Files to modify:**
- `aida-core/src/scaffolding/mod.rs` — add `codex mcp add` to init workflow
- Detection: `which codex` to check if installed

### Phase 2: Enhanced AGENTS.md

Update the generated AGENTS.md to match the depth of CLAUDE.md:
- Include distributed mode instructions
- Include GitHub integration commands
- Include analytics commands
- Reference MCP tools (since Codex will have them via Phase 1)
- Include workflow recipes for `codex exec`

**Example enhanced AGENTS.md sections:**

```markdown
## MCP Tools Available

This project has AIDA configured as an MCP server. You can use these tools:
- `list_requirements` — list all requirements with optional filters
- `show_requirement` — show full details of a requirement
- `search_requirements` — search by keyword
- `add_requirement` — create a new requirement
- `add_comment` — add a comment to a requirement

## Non-Interactive Workflows (codex exec)

# Implement a specific requirement
codex exec "Implement FR-042. Show the requirement first, then create the code with trace comments."

# Sprint standup
codex exec "Review git log since yesterday, cross-reference with AIDA requirements, and generate a standup report."

# Code review with traceability check
codex review --base main "Verify all new functions have trace comments linking to AIDA requirements."
```

**Files to modify:**
- `aida-core/src/scaffolding/codex_md.rs` — rewrite AGENTS.md generation

### Phase 3: Codex Skills (Parity with Claude Code)

Create `.codex/skills/` with Codex-compatible skill files. Codex doesn't have Claude Code's skill system, but it reads files from the project when given context. The approach:

Create markdown files that Codex can reference via AGENTS.md:

```
.codex/skills/
  aida-req/SKILL.md          — requirement creation workflow
  aida-implement/SKILL.md    — implementation with traceability
  aida-grill/SKILL.md        — design interrogation
  aida-commit/SKILL.md       — commit with requirement linking
```

These mirror the Claude Code skills but are structured for Codex's conventions (SKILL.md in subdirectories).

**Files to create:**
- `aida-core/templates/codex-skills/` directory with Codex-formatted skill files
- `aida-core/src/scaffolding/mod.rs` — scaffold `.codex/skills/` during init

### Phase 4: `codex exec` Recipes

Pre-built recipes that users can run non-interactively:

```bash
# Daily standup
codex exec "$(cat .codex/skills/aida-standup/SKILL.md)"

# Implement next approved requirement
codex exec "List approved requirements with 'aida list --status approved'. Pick the highest priority. Implement it following the aida-implement workflow."

# End-of-day capture
codex exec "Review today's git commits. For each commit, check if it has a requirement trace. Create requirements for any untraced work."
```

### Phase 5: Review Integration

Wire `codex review` to check AIDA traceability:

```bash
# Custom review that checks requirement traceability
codex review --base main "For each new or modified source file:
1. Check if it has trace comments (// trace:SPEC-ID)
2. If not, flag it as untraced
3. For traced files, verify the referenced requirement exists in AIDA
4. Report: N files traced, M files untraced, K references to non-existent requirements"
```

This could be packaged as a script:
```bash
aida codex review   # wrapper around codex review with AIDA-specific instructions
```

## Cross-Agent Strategy

The goal is not Codex OR Claude Code — it's BOTH. AIDA should be the **shared context layer** that any AI agent can use:

```
                    AIDA (MCP Server)
                         │
              ┌──────────┼──────────┐
              │          │          │
         Claude Code   Codex CLI   Future agents
         (skills)      (MCP)       (MCP)
```

- Claude Code gets skills (`.claude/skills/`) + MCP + CLAUDE.md
- Codex CLI gets MCP + AGENTS.md + `.codex/skills/`
- Future agents get MCP (the universal integration point)

MCP is the common protocol. Skills are agent-specific sugar.

## What to Implement Now

1. **`aida init`** should detect `codex` in PATH and auto-configure MCP
2. **AGENTS.md** should be as rich as CLAUDE.md
3. **MCP is the bridge** — one server, multiple agents
