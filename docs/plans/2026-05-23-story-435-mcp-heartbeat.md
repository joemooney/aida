# STORY-435 — MCP heartbeat busy/idle tracking for agent registry (EPIC-31 Phase 4)

Date: 2026-05-24 · Specs: STORY-435 (parent: EPIC-31, Phase 4) · Status: Plan · Complexity: Small-Medium

## Summary

Phase 1 (STORY-431) shipped the agent registry. Today's status classifier is binary: pid dead -> stale, current_spec set -> busy, else idle. There's no freshness signal — an agent that finished an hour ago looks identical to one mid-tool-call. STORY-435 makes busy/idle a freshness signal: last_active_at < N seconds (default 30s, configurable) OR active "Live" lease covering the agent's worktree.

The MCP server already touches every JSON-RPC request via touch_mcp_agent. Mechanism exists; classification doesn't use it yet.

## Approach (5 changes)

1. New classifier inputs: classify_status(entry, pid_alive) -> classify_status(entry, pid_alive, ctx) where ctx = AgentClassifyContext { now, threshold_secs, has_live_lease }
2. Config section: new [agent_registry] block in .aida/config.toml with busy_threshold_secs = 30 (default)
3. Lease correlation: pass set of Live-lease worktrees into list_agent_views
4. Status display polish: format_agent_status_lines appends compact (Xs)/(Xm) freshness hint
5. Regression test (spec-mandated): 3 agents with different activity patterns -> correct state for each

Classifier branches (precedence): !pid_alive -> Stale; now-last_active_at < threshold -> Busy; live_lease covers entry.worktree_path -> Busy; else -> Idle.
