# Plan: EPIC-26 — AIDA TUI (process-supervisor shell hosting Claude Code)

Date: 2026-05-15
Specs: EPIC-26 (+ child STORYs filed via Followups)
Status: Draft
Complexity: ~1800 prod LOC, ~320 test LOC, 9 commits, risk medium-high

## Context

AIDA is CLI-only today: Claude Code is the outer shell, and acting on AIDA
state mid-conversation means exiting Claude, running `aida ...`, then
cold-resuming. EPIC-26 flips the relationship — a thin **TUI becomes the outer
shell** that hosts Claude Code sessions as PTY children. The user drops out of
a live Claude session to a status overlay, takes one-keystroke actions, drops
back into the *same* conversation. It is "tmux for AIDA workflows," not a
dashboard. Per the Trojan-horse positioning, the TUI is intentionally shallow
on first sight; its depth (graph, queue, lifecycle, `/goal` composition)
surfaces through use. Every primitive it needs already shipped (TASK-112,
TASK-220, TASK-242, …) — this EPIC is composition, not new platform.

## Approach

Add a new workspace library crate **`aida-tui`** and an `aida tui` subcommand.
The TUI is a synchronous, thread-per-PTY supervisor: it owns the real terminal
in raw mode, reserves the bottom row for a status strip, and hosts each Claude
session in a `portable-pty` PTY whose child is **`aida queue work <scope>
--session-id <uuid>`** (which `exec()`s into `claude`). Rendering uses the
**tmux/passthrough model**: a focused tab blits PTY output straight to stdout
(Claude renders natively, zero parser cost); a `vt100::Parser` is fed
continuously so the screen can be repainted on tab-switch / overlay-close. A
prefix key (`Ctrl-a`, configurable) toggles a command mode; `prefix o` opens a
`ratatui` status overlay built from `aida status --json`; quick actions and
`/goal` drain buttons shell out to existing `aida` subcommands. Crash recovery
is a `.aida/tui-state.json` file recording each tab's Claude `session_id` for
re-attach via TASK-112's `--resume`. Develop behind an `aida-cli` `tui`
feature (default-off); the final docs STORY flips it default-on.

### Diagram — control flow & input routing

```
                    ┌──────────────────────────────────────────┐
   real terminal ───┤  aida tui  (supervisor, crossterm raw mode)│
   stdin / stdout   │   TabManager [tab0*][tab1][tab2]           │
                    │   bottom 1-row status strip                │
                    └───────────────┬──────────────────────────-┘
                                    │ PTY master (rows = H-1, cols = W)
                                    ▼
            aida queue work <scope> --session-id <uuid>   (per tab)
                                    │ exec()  (session.rs::exec_claude*)
                                    ▼
                          claude code  — renders natively

  Input router (per keystroke):

   FOCUSED ──prefix key──► COMMAND ──o──► OVERLAY ──esc/q──► FOCUSED
      ▲ keystrokes            │  ├─d──► detach: quit, Claude .jsonl persists
      │ pass straight         │  ├─n──► new tab (aida queue work picker)
      └ through to claude     │  ├─1..9 / [ ] ──► switch tab ──► FOCUSED
                              │  └─prefix──► send literal prefix ──► FOCUSED
   OVERLAY: ratatui draws panels; quick actions run `aida ...` subprocesses;
            on close, repaint focused tab from its vt100 snapshot + SIGWINCH.
```

## Decisions

The eight EPIC design forks, each resolved:

- **Fork 1 — Hosting model**: PTY-host via `portable-pty` (wezterm's
  cross-platform crate; Unix openpty + Windows ConPTY). **Rationale**: full
  control + portability + no external dependency; tmux-pane needs tmux
  installed and can't own keybindings cleanly; window-manager multiplexing is
  over-scoped and the EPIC's "NOT a tmux replacement" anti-pattern rules it out.
- **Fork 2 — Session focus model**: session-as-tab — N hosted concurrently,
  one focused. **Rationale**: acceptance requires multi-session management;
  multi-pane splits a full-screen Claude TUI awkwardly and is "surface-busy"
  (anti-pattern); single-session can't satisfy "list/switch."
- **Fork 3 — State sync**: poll-based, reusing `.aida/cache.db`
  stale-detection. The overlay runs `aida status --json` on open and a
  background refresh every 4s **while the overlay is visible only** (no polling
  while Claude is focused — Claude owns the screen). `status --json` already
  exposes `cache.fresh` (recorded HEAD vs git HEAD). **Rationale**:
  git-hook-driven needs hooks that don't fire on remote updates; MCP-pushed
  needs a net-new notification channel the MCP server lacks today (filed as a
  Followup).
- **Fork 4 — Notifications**: dedicated activity-log panel inside the overlay +
  a one-line badge in the bottom status strip. No libnotify/desktop.
  **Rationale**: portability (SSH/headless); the strip is always-visible chrome
  that never interrupts Claude's screen.
- **Fork 5 — `/goal` composition**: autonomous-mode buttons shell out to `aida
  goal --invoke ...` (TASK-242) to derive the `/goal` line, then inject it into
  the focused Claude PTY as input. Never hand-write `/goal` text. Two distinct
  buttons — **Drain to review** and **Drain to merge** — make the workflow
  choice explicit. **Rationale**: dodges the 2026-05-15 literal-phrasing trap.
- **Fork 6 — First vertical**: STORY-1 (PTY host + strip + clean exit +
  `--session-id` plumbing) and STORY-2 (read-only overlay + 3 quick actions)
  together = the minimum that proves the Trojan-horse test.
- **Fork 7 — Exit model**: any-time-exitable via a configurable prefix key.
  `prefix d` detaches (quit TUI; Claude `.jsonl` conversations persist on
  disk); `prefix q` quits with a confirm. Plain keystrokes pass straight to
  Claude. **Rationale**: "q from overlay only" is too captive; "Ctrl-C twice"
  collides with Claude's own Ctrl-C handling.
- **Fork 8 — Crash recovery**: `.aida/tui-state.json` records each tab's
  `{session_id, scope, role, worktree}`. A TUI crash kills the PTY children but
  the Claude conversations are durable `.jsonl` files (TASK-112). On relaunch
  `aida tui` reads the state file, lists orphaned sessions, and re-attaches each
  by spawning `aida queue work <scope> --resume <session_id>`.

Additional decisions:

- **New crate, not `aida-cli/src/tui/`**. `main.rs` is already 1.6 MB; the TUI
  pulls heavy deps (`ratatui`, `portable-pty`, `vt100`). A library crate
  `aida-tui` with `pub fn run()` keeps deps and tests contained and matches the
  5-crate workspace convention. `aida-cli` gets a thin `Command::Tui` dispatch.
- **Sync + threads, not tokio**. PTY pumping is two blocking reader threads +
  an input thread feeding an `mpsc` event channel; `ratatui`/`crossterm` event
  loops are sync. `dev serve`'s tokio supervisor is a different subsystem — no
  reuse pressure.
- **Passthrough rendering, not embedded `tui-term`**. One tab is focused at a
  time (Fork 2), so Claude never needs to render inside a widget. `vt100` is
  used only for the off-screen snapshot used to repaint on return.
- **TUI child = `aida queue work`, never `claude` directly**. All lease /
  worktree / manifest / permission-mode / plan-brief logic is inherited;
  Claude-flag drift is absorbed in one existing place (`session.rs::exec_claude`).
- **Transitional `tui` feature flag** (one flag, not a forest). Default-off
  through development so partial work never ships in a release binary
  ("hide if half-done"); STORY-6 flips `aida-cli` to `default = ["tui"]`.
- **`Command::Tui` dispatches early**, before storage init — like `McpServe` /
  `Goal` / `Statusline`. The supervisor holds no storage handle; it shells out.

## Files (in build-order)

### `Cargo.toml` (workspace) — register the crate

- `[workspace] members`: add `"aida-tui"`.
- `[workspace.dependencies]`: add `ratatui`, `crossterm` (match ratatui's
  pinned version), `portable-pty`, `vt100`.

### `aida-tui/Cargo.toml` — new library crate

- `[lib]` crate `aida-tui`; deps: `ratatui`, `crossterm`, `portable-pty`,
  `vt100`, `anyhow`, `serde`/`serde_json`, `uuid`, `dirs`. Unix: `libc` for
  SIGWINCH.

### `aida-tui/src/lib.rs` — entry point

- `pub struct TuiOptions { scope: Option<String>, no_recover: bool }`.
- `pub fn run(opts: TuiOptions) -> Result<()>`: install the panic hook +
  terminal-restore guard, build `App`, run the event loop.

### `aida-tui/src/term.rs` — terminal lifecycle

- `struct TermGuard`: on construction enters raw mode + alt-screen; `impl Drop`
  restores cooked mode, leaves alt-screen, shows the cursor.
- `fn install_panic_hook()`: chains a hook that runs the same teardown before
  the default panic print, so a panic never leaves a broken terminal.
- `fn pty_rows(term_rows: u16) -> u16`: `term_rows.saturating_sub(1).max(1)` —
  reserve the status strip.

### `aida-tui/src/pty.rs` — PTY host

- `struct PtyHost { master, child, parser: Arc<Mutex<vt100::Parser>>,
  reader_handle }`.
- `fn spawn(argv: &[String], rows: u16, cols: u16) -> Result<PtyHost>`: open a
  PTY pair, spawn the child, start a reader thread that (a) feeds the
  `vt100::Parser` and (b) forwards bytes to the active-output channel.
- `fn resize(&self, rows, cols)`, `fn write_input(&self, bytes: &[u8])`,
  `fn snapshot(&self) -> Vec<u8>` (ANSI re-render of the vt100 screen),
  `fn is_alive(&self) -> bool`.

### `aida-tui/src/tab.rs` — tab model

- `struct SessionTab { session_id: String, scope: String, role: Option<String>,
  worktree: PathBuf, pty: PtyHost, title: String }`.
- `struct TabManager { tabs: Vec<SessionTab>, focused: usize }` with
  `add`, `remove`, `next`, `prev`, `switch_to`, `focused()` — index math
  clamps/wraps and refocuses a neighbor on removal.
- `const MAX_TABS: usize = 4` (soft cap; overridable via config).

### `aida-tui/src/statusbar.rs` — bottom 1-row strip

- `fn render(buf, area, tabs: &TabManager, badge: Option<&str>)`: tab list
  (`[1·EPIC-26][2 BUG-9]`), notification badge, `prefix o = overlay` hint.

### `aida-tui/src/app.rs` — state + event loop

- `enum Mode { Focused, Command, Overlay }`.
- `struct App { tabs: TabManager, mode: Mode, prefix_key: KeyEvent, overlay:
  OverlayState, activity: Vec<ActivityEntry> }`.
- `fn route_key(&mut self, key) -> Routing`: the Focused→Command→Overlay state
  machine; in `Focused`, non-prefix keys → `Routing::Passthrough`.
- `fn run_event_loop(&mut self)`: select over the input channel, PTY-output
  channel, and a SIGWINCH/resize event; repaint the focused tab from its
  `vt100` snapshot when leaving Overlay.

### `aida-tui/src/overlay.rs` — status overlay (ratatui)

- `struct OverlayModel` mirroring `aida status --json` (session/role/branch/
  pr/queue/cache) + a queue-list section.
- `fn fetch() -> Result<OverlayModel>`: run `aida status --json` (cache-only
  first via `--no-ci`, then a background `gh`-backed refresh).
- `fn render(frame, model, selected_action)`: panels — Queue, Leases,
  Branch/PR/CI, Activity log, and the quick-action / `/goal` menu.

### `aida-tui/src/actions.rs` — quick actions & `/goal`

- `enum QuickAction { QueueWork, SessionEnd, PrView, DrainToReview,
  DrainToMerge, ... }`.
- `fn argv(action, ctx) -> Vec<String>`: builds the subprocess command —
  `DrainToReview`/`DrainToMerge` build `["aida","goal","--invoke", ...]` and
  the resulting `/goal` line is injected into the focused PTY via
  `PtyHost::write_input`.
- `fn run(action, ctx) -> ActivityEntry`: spawn, capture output into the
  activity log, surface exit status.

### `aida-tui/src/state.rs` — crash recovery

- `struct TuiState { tabs: Vec<TabRecord> }`, `TabRecord {session_id, scope,
  role, worktree}`.
- `fn save(root, &TuiState)` / `fn load(root) -> Option<TuiState>` —
  `.aida/tui-state.json` (covered by the existing `.aida/*` gitignore rule).
- `fn reattach_argv(rec) -> Vec<String>`: `["aida","queue","work",scope,
  "--resume",session_id]`.

### `aida-cli/Cargo.toml` — wire the crate in

- `aida-tui = { path = "../aida-tui", optional = true }`; `[features] tui =

## Risks + gotchas

1. **Raw mode not restored on panic** → broken terminal. **Mitigation**:
   `TermGuard` RAII restore on `Drop` + a chained panic hook running the same
   teardown before the panic print.
2. **TUI crash kills PTY children mid-work.** **Mitigation**: Claude
   conversations are durable `.jsonl` files (TASK-112); `tui-state.json`
   records every `session_id`; relaunch re-attaches via `aida queue work
   --resume`. A graceful `prefix d` detach does *not* kill children.
3. **Claude Code flag drift** (`--session-id` / `--resume` / `--name` /
   `--permission-mode`). **Mitigation**: the TUI never calls `claude` directly
   — only `aida queue work`, so drift is absorbed in the single existing
   `session.rs::exec_claude`.
4. **SIGWINCH races** — real-terminal resize must propagate to every PTY.
   **Mitigation**: central SIGWINCH handler resizes the focused PTY
   immediately, background tabs lazily on switch; PTY rows always
   `term_rows − 1`.
5. **Repaint on overlay-close / tab-switch** — Claude's screen must be
   restored. **Mitigation**: a continuously-fed `vt100::Parser` per tab; on
   return, blit the snapshot then send SIGWINCH to nudge a native repaint.
6. **Multi-session resource contention** (N Claude children = N× CPU/tokens/
   API). **Mitigation**: soft cap `MAX_TABS = 4` (config `[tui] max_tabs`);
   the strip shows the count; a new tab past the cap warns.
7. **Quick action vs. live lease conflict** — `aida queue work` / `session end`
   run while a child holds a lease on the same scope. **Mitigation**: actions
   are subprocesses whose output (incl. existing lease-conflict errors) lands
   in the activity log; `session end` confirms first. No re-checking — trust
   `aida`'s own guards.
8. **Prefix-key collision** with Claude or a nested shell. **Mitigation**:
   configurable `[tui] prefix_key` (default `Ctrl-a`); a double-press sends one
   literal prefix byte to the child.
9. **New deps need crates.io at build time** (`ratatui`, `portable-pty`,
   `vt100`) — may be blocked by a restrictive network policy. **Mitigation**:
   add the deps in the first commit so any fetch failure surfaces immediately;
   all three are mature, widely-vendored crates.
10. **`aida status --json` stalls on `gh`** (PR/CI shell-out). **Mitigation**:
    overlay first paints `--no-ci` (cache-only, sub-ms), then a background
    thread fetches the `gh`-backed section and repaints when it lands.
11. **Windows** — `exec()` semantics and PTY differ. **Mitigation**:
    `portable-pty` handles ConPTY; `crossterm` is cross-platform. Unix is the
    primary target; Windows is best-effort and explicitly out of STORY-1 scope.

## Verification

```bash
set -euo pipefail
TMP=$(mktemp -d); cd "$TMP" && git init -q && aida init >/dev/null
aida add --title "tui smoke" --type story --status approved >/dev/null
SPEC=$(aida list --status approved --json 2>/dev/null | head -c0; aida list | grep -oE 'STORY-[0-9]+' | head -1)

# 1. subcommand is wired
aida tui --help | grep -qi 'no-recover'

# 2. caller-minted session id threads through (positive)
UUID=$(uuidgen)
aida queue add "$SPEC" >/dev/null
aida queue work "$SPEC" --session-id "$UUID" --no-launch
aida session manifest --json 2>/dev/null | grep -q "$UUID" \
  && echo "PASS: session-id override recorded"

# 3. overlay data source parses
aida status --json --no-ci | python3 -c 'import json,sys; json.load(sys.stdin)' \
  && echo "PASS: status --json parses"

# 4. /goal composition (positive) — TUI drain buttons consume this
aida goal --spec "$SPEC" --invoke | grep -q '^/goal ' \
  && echo "PASS: aida goal --invoke emits a /goal line"

# 5. negative — bad session id rejected
aida queue work "$SPEC" --session-id "not-a-uuid" --no-launch 2>&1 \
  | grep -qi 'uuid' && echo "PASS: non-UUID session id rejected"

# 6. negative — tui outside a repo errors cleanly
( cd /tmp && aida tui 2>&1 | grep -qi 'not.*\(a \)\?\(git \)\?repo\|aida init' ) \
  && echo "PASS: tui outside repo errors clearly"

# 7. PTY smoke (if `script` available) — launch + prefix-quit + clean exit
if command -v script >/dev/null; then
  printf '\x01q' | script -qec "aida tui" /dev/null >/dev/null 2>&1 \
    && echo "PASS: tui launches and prefix-quits cleanly"
fi

cargo test -p aida-tui -p aida-cli --features tui
```
