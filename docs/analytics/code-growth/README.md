# Historical code growth (Tokei)

Repeatable, read-only analysis of how the codebase grew across first-parent
history of `main`. Generated by `scripts/analyze_code_growth.py`.

The analysis only reads git history (`git log`, `git archive`). It does not
touch the work tree, index, refs, or any AIDA store/session state. Snapshots
are extracted into a private scratch directory with a private `HOME`, so no
user Tokei configuration applies.

## Rerun

Requires `tokei` on `PATH` (checked against Tokei 12.1.2), `git`, `python3`,
and `matplotlib` for the PNGs.

```bash
# monthly samples through the current main tip, outputs next to this README
python3 scripts/analyze_code_growth.py --ref main --out docs/analytics/code-growth

# other cadences: day | week | month | quarter | year; --every N thins periods
python3 scripts/analyze_code_growth.py --cadence quarter --out /tmp/growth-quarterly
python3 scripts/analyze_code_growth.py --cadence week --every 2 --no-charts --out /tmp/growth-biweekly

# tests (pure tests always run; Tokei-backed fixture tests skip without tokei)
python3 -m unittest tests/test_analyze_code_growth.py
```

A full monthly run exports ~11 historical trees and takes roughly 10 minutes,
dominated by `git archive` of older commits. The exit code is non-zero if the
tip reconciliation fails (`--allow-mismatch` overrides).

## Sampling

- History is `git log --first-parent <ref>`, so merged side-branch commits are
  never sampled; only what landed on the mainline.
- Periods are calendar periods in UTC by committer date. Each period
  contributes its **last** first-parent commit. Periods with no commits (for
  example April 2026 here) produce no sample.
- The current tip is always the final sample, even when its period is not
  finished (`kind: tip`, `partial: true` in the JSON).
- `--every N` keeps every Nth period counting back from the tip.

## Assumptions and exclusions

- **Tracked files only.** Trees come from `git archive`, so untracked and
  ignored files never count. Tokei runs with `--no-ignore` so that tracked
  files matching `.gitignore` are still counted. A plain `tokei .` in a
  working checkout honors `.gitignore` and may report slightly fewer lines.
- **Symlinks** are skipped (Tokei does not follow them); counts per sample are
  in `samples[].symlinks_skipped`.
- **Embedded languages are not double counted.** The CSV/JSON rows use each
  file's own-language Tokei stats, which sum exactly to Tokei's `Total`. Code
  Tokei attributes to embedded languages (JavaScript/CSS inside HTML, fenced
  blocks inside Markdown, Markdown inside Rust doc comments) is exported
  separately in `code-growth-embedded.csv` and never added to totals.
- **Generated, vendored & data artifacts** are kept in the CSV/JSON and in the
  reconciliation, but excluded from all presentation charts; each chart
  states this in its footer. Generated server code with `#[test]` markers, for
  example, is counted in the raw/per-bucket Rust evidence but not plotted. The
  supporting chart additionally notes that legacy requirement data
  (`aida-store/`) moved off the code branch, which explains why that data is
  not part of the supporting corpus.
- Inline `#[cfg(test)]` modules inside production files stay in their
  component bucket; only separate test files and directories count as tests.
  The Rust test chart covers that gap from the other side.
- The mapping from legacy directory names to current buckets (for example the
  early `requirements-manager/` monolith to Core) is approximate.

## Delivery cadence limitation

Commit counts are exact first-parent commits. PR counts are **inferred from
commit subjects** (`(#N)` suffix, `Merge pull request #N`, `(!N)`,
`See merge request ...!N`), de-duplicated per period. Work merged without such
a subject, and early history before PR-style subjects were used, is
undercounted (the first months show zero PRs; the chart footer says so
explicitly, derived from the data, and it is not a delivery pause). Periods are enumerated
over the finite calendar range between the earliest and latest period seen,
so backdated or out-of-order first-parent dates never drop commits (idle
periods show zero). A period is marked partial when it ends after the date of
the actual ref tip (date-as-of semantics; a backdated tip also marks
later-dated periods partial). The chart title names the selected ref.

## Rust test markers (heuristic)

Counts attribute lines at the start of a line, outside `//` comments:
`#[test]` (plain), `#[<path>::test]` such as `#[tokio::test]` (async), and
`#[rstest]`. `#[case]` rows are not multiplied; block comments, string
literals and `#[cfg_attr(..., test)]` are not parsed. Treat the figure as a
growth indicator, not an exact test count.

## Tip reconciliation

The final sample's bucketed totals are compared against an independent Tokei
run on a second export of the same tip: per language `code`, `comments`,
`blanks`, and file counts, plus Tokei's `Total`. The result is stored in
`code-growth.json` under `reconciliation` (`ok: true` for the committed run).
