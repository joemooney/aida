01 / THE HUMAN–AGENT LOOPOPERATING MODEL · NOT A LIVE RUN

A conversation is the front door.

People can author code, pair with agents and review each other’s work. You do not need to become a command-line workflow operator. Ask an AIDA-aware agent to capture intent, settle the criteria and prepare the change. The agent uses the CLI or typed MCP tools; you stay focused on the outcome and the decisions.

A WORKED EXAMPLE

“Add login throttling.
Keep me in the review.”

An illustrative conversation, not a separate AIDA chat service. Your coding agent follows the installed guidance and acts within its available authority.

YOU / INTENT

Check what we already decided. Help me define the behavior, record the requirement, and build it for my review.

AGENT / OPERATIONS

Read the graph. Capture the draft. Surface unresolved choices. Route approved work to supervised delivery. Implement through CI and stop at the human handoff.

RETURN / EVIDENCE

The requirement, the change, validation results, review findings and anything still waiting on a decision.

02 / THE DELIVERY PATH

EACH TRANSITION HAS A RESPONSIBILITY

From intent to integration.
With context at every handoff.

01 / CAPTURE

Make the work explicit.

The agent checks existing context, captures a spec and exposes the acceptance criteria. Filing a draft is distinct from authorizing the work.

02 / CLARIFY

Resolve the forks.

The advisor helps settle design choices, records decisions and recommends the execution mode. Pending decisions remain visible.

03 / IMPLEMENT

Give work an owner.

An implementer works against the spec in an isolated worktree. Leases and queues coordinate which session owns the work.

04 / VALIDATE

Check the result.

Tests and CI provide evidence against the intended behavior. Passing checks and a completed agent session are different facts.

05 / REVIEW

Separate the judgment.

An independent reviewer checks the change and records a verdict against the exact commit. The implementer's summary is not that review.

06 / INTEGRATE

Land through the gates.

Merge policy checks review, CI, holds and authority. The selected mode determines whether a person or an authorized agent takes the next step.

03 / PROJECT MEMORY

The session ends.
The intent stays.

AIDA keeps the graph of requirements, decisions and relationships in Git. Code traces and linked commits connect that intent to implementation. The next agent can recover context without inheriting the previous conversation.
