HOW RUNNING REVIEWBENCH IMMEDIATELY IMPROVED AIDA’S ENGINE

+33.3% High-TP Recall

Our initial v1 run on ReviewBench pinpointed two concrete causes for the only two missed High-severity Golden TPs:

  1. Full Target File Context in Diff Batches (build_batch_review_prompt): In v1, diff mode sent only the 3-line-context git diff patch to Pass-1 Finder. On k1LoW/gh-copilot-review#9 (Go), MinimizeCopilotComments() lay 15 lines above the diff hunk in cmd/root.go. Appending the full target file from content_cache (when ≤ 32 KB) allowed Pass 1 & Pass 2 in v2 to catch High Golden TP #11 (cmd/root.go:73-80) with an exact line anchor.
  2. Preserving exacerbated-by-pr Defects in Challenger Condition 2 (Change-Relevant): In v1, Pass-1 Finder caught the Tier-A High-severity Path Traversal in PierreJanineh/TechDebtMCP#135 (src/server/handlers.ts:438-454, missing path.isAbsolute() / path.resolve()), but Pass-2 Challenger dismissed it as pre-existing. Clarifying Condition 2 to include defects exacerbated by adding new filesystem calls in a touched function caused v2 to confirm C3 (src/server/handlers.ts:438-440).

Why ReviewBench §7.3 Stratifies Recall by Severity

HIGH HIGH-SEVERITY RECALL + LOW LOW-SEVERITY RECALL IS BY DESIGN

Methodology §7.3

ReviewBench’s methodology documentation (§7.3) explicitly notes:

“An agent designed to surface only the most impactful issues and to suppress noise should be evaluated on recall stratified by severity. High recall on severity = high paired with deliberately low recall on severity = low is a feature, not a failure; an unstratified recall number would penalize this agent unfairly.”
