THE EVERYDAY ENTRY PATH

The same conversation.
A record that stays.

Discuss, implement, debug and review as usual. Your AIDA-aware agent consults and maintains the project’s requirements and decisions. You keep both the system and the shared intent that makes it easier to maintain, enhance and hand over. You can write code yourself or pair with the agent; autonomous delivery is an additional choice.

01

ONE-TIME / OPERATOR SETUP

Connect the tools.

An operator or authorized setup agent installs AIDA, configures the coding-agent runtime and initializes the project. Vendor authentication and model access are separate from AIDA.

Show operator setup commands
curl -sSL https://raw.githubusercontent.com/joemooney/aida/main/scripts/install.sh | bash
aida --version
cd my-project
aida init

Linux x86_64 and arm64. Existing/adopted projects use the appropriate attach or projection flow; inspect their setup before running init. MCP is an explicit opt-in with --with-mcp.

03

WHEN DELEGATING / SELECT THE CONTRACT

Choose the handoff when delegating.

The agent captures drafts and recommends the delivery mode. An authorized advisor handles approval and routing. Start with supervised delivery: agents implement through CI; a person reviews and merges.

HUMAN / INSPECT THE RESULT

Ask for the evidence.

Show me the acceptance criteria, what changed, how each criterion was checked, the review findings and anything still waiting on me.

Expand delegation as your validation and operating evidence justify it. Configuring more autonomy is a deliberate policy choice.
