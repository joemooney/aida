Why General-Purpose Agent Reviews Fail

FOUR FAILURE MODES OF UNCONSTRAINED LLM DIFF SKILLS

Unconstrained Prompting
  • Incomplete file coverage (Attention Drop-Off): On changesets over 400–1,000 LoC, general-purpose agents skim files in the middle of the prompt and silently omit them from the review.
  • Line-number position drift: LLMs routinely miscalculate line numbers in unified diff hunks, attaching findings to unrelated code lines.
  • Vague checklist variance: Generic prompts ("check error handling and concurrency") cause models to stop after spotting a single ? operator.
  • Intent blindness: Standalone code-review tools inspect syntax in isolation without knowing the spec's ## Acceptance criteria or AIDA authority invariants.

How AIDA's Hybrid Architecture Solves It

DETERMINISTIC RUST SUBSTRATE × INDEPENDENT REVIEWER SEAT

Substrate as Bouncer
  • Sealed inventory. Rust hashes the file inventory and records whether each file contains the literal trace: marker.
  • Batching. A same-stem heuristic groups likely source and test companions. The default cap is 12,000 estimated tokens per batch. Preparation lists over-cap files and their token estimates in the exclusions and coverage report, then batches the remaining files.
  • Whole-File Substring Security & Concurrency Facets: Injects ANSSI unsafe/FFI, Tokio async cancellation, subprocess option-injection, and macro checklists only when matching substrings appear anywhere in the file.
  • Snippet anchoring. The CLI locates matching quoted lines in the target file.
02 / DETERMINISTIC ENGINEERING SUBSTRATE

The Four Clean-Room Rust Pillars

The core logic lives in aida-core. The CLI calls Git to collect its inputs.

Pillar 1 · Sealed Inventory & Optional Coverage Ledger

classify_diff_inventory & verify_coverage_ledger

SHA-256 Sealed

Git is required in every mode. Workspace mode compares local changes with HEAD and includes non-ignored untracked files. Range mode uses the merge base of the supplied refs (target defaults to HEAD). PR mode needs forge base/head metadata and local revisions. Commit mode needs the commit and its parent. Scan mode uses git ls-files --cached --others --exclude-standard under the selected paths.

  • Explicit Exclusion Taxonomy: Automatically filters binary_file, pure_deletion, generated_or_lockfile (Cargo.lock, target/), aida_substrate (.aida-store/, .aida/cache*), secret_sensitive_path (.env*, *.pem, *.key), and user_excluded:<glob>.
  • Fail-Closed Coverage Verification: --verify-coverage <ledger.json> requires 100% of reviewable_files to be marked reviewed or skipped (with a non-empty reason).

Pillar 2 · Token-Budgeted Semantic Batching

bundle_review_batches & canonical_module_stem

12k estimated target

A same-stem heuristic groups likely source and test companions. The default cap is 12,000 estimated tokens per batch. Preparation lists over-cap files and their token estimates in the exclusions and coverage report, then batches the remaining files.

  • Source + Companion Test Pairing: Normalizes foo.rs, foo_test.rs, foo_tests.rs, test_foo.py, and foo.test.ts to a shared stem as a heuristic for identifying likely companions.
  • Crate-Qualified Generic Stems: Entry-point filenames (lib.rs, mod.rs, main.rs, index.ts) are qualified by parent directory (aida-core/src/lib vs aida-cli-lib/src/lib) so unrelated crates never collide.

Pillar 3 · Requirement Graph & Trace Linkage

resolve_linked_specs & has_trace_comment

Intent-Aware

Connects every code review directly to AIDA's git-canonical requirement store (.aida-store).

  • Automatic Spec Extraction: Parses completing and Refs spec IDs from commit trailers in merge_base..head (or explicit --specs CSV) and injects each spec's ## Acceptance section into the preparation bundle.
  • Trace marker. The flag records the substring trace:. It does not validate comment syntax or resolve a spec ID.

Pillar 4 · Snippet Line-Anchoring & Citations

anchor_snippet_lines & verify_observation_citations

Zero Line Drift

Replaces LLM line-number guessing with deterministic two-pass sliding-window resolution against the target git revision (git show <sha>:<path>).

  • Pass 1 (Exact) & Pass 2 (Trimmed Whitespace): Resolves quoted existing_code to 1-based inclusive (start_line, end_line) spans, breaking ties by minimum distance to an optional start_line hint.
  • Library-only Observation Citation Verifier: Validates every [[obs-NNNNNN]] evidence tag in a review report against recorded observations, flagging unknown or errored IDs.
03 / HIGH-SIGNAL, ZERO-BLOAT PROMPT ENGINEERING

Core Playbooks + Whole-File Substring Security Facets

Synthesizes the Rust API Guidelines, ANSSI Secure Rust, Tokio Concurrency Patterns, and Google Engineering Practices mapped directly to AIDA's finding classes.

Interactive Playbook & Conditional Facet Explorer

CLICK EACH TAB TO INSPECT THE ALWAYS-ON CORE AND WHOLE-FILE SUBSTRING CONDITIONAL FACETS

Zero Token Overhead When Absent

Trigger: Always active on **/*.rs. Maps directly to AIDA's aida review record --finding-class taxonomy:

  • Anti-noise & evidence floor: Do not duplicate diagnostics that rustc, the borrow checker, cargo clippy, or rustfmt catch reliably. Verify reachable call sites, trait bounds, and input boundaries before flagging.
  • Fail-closed error semantics (fail-open, absent-evidence-reads-as-good): Flag any .unwrap(), uncontextualized .expect(""), or panic! in production paths. Flag Result or Option values silently mapped to empty/success defaults (unwrap_or_default, if let Ok(...)) where an I/O, git, or parse failure is misread as "0 items".
  • Ownership, allocations & algorithmic complexity (perf): Flag O(n^2) nested scans where a BTreeMap/HashMap/HashSet or sorted index suffices, repeated Regex::new or collection rebuilds inside loops, and avoidable .clone()s.
  • UTF-8, integer casts & slice bounds (portability): Flag byte-index string slicing (&s[a..b]) not proven to lie on UTF-8 character boundaries, unchecked slice indexing, and lossy as numeric casts (u64 as usize).
  • Caller contract & AIDA traceability (contract-drift, incomplete-fix, untested-path): Verify every call site when a signature or behavior changes, confirm // trace:<SPEC-ID> | ai:<tool> presence, and ensure tests falsify failure/refusal paths.

Triggered only when reviewed files contain: Command::new, std::fs::, OpenOptions, Path::new, PathBuf, serde_json::, serde_yaml::, or toml::.

  • Subprocess option injection: Never build commands via shell string interpolation; validate user/ref inputs with reject_option_like and pass --end-of-options (END_OF_OPTIONS) or -- before positional refs/paths.
  • Path traversal & TOCTOU: Reject Component::ParentDir (..) and unexpected RootDir on external relative paths, verify symlink/containment boundaries, and check that revision-pinned reads never silently fall back to the live working tree.
  • Schema & deserialization hygiene: Bound untrusted input sizes before parsing, use #[serde(deny_unknown_fields)] on authority/verdict payloads, and preserve #[serde(default)] backward compatibility on config files.

Triggered only when reviewed files contain: async fn, .await, tokio::, Mutex, RwLock, Atomic, std::thread, or select!.

  • Locks across .await & blocking in async: Never hold a synchronous std::sync::Mutex/RwLock guard across .await, and do not run blocking filesystem/subprocess I/O on async worker threads.
  • Cancellation safety: In tokio::select! loops or cancellable futures, ensure dropping a future mid-flight cannot lose buffered data, leave partial writes, or leak a lock/permit.
  • Lock ordering & atomics: Verify consistent lock acquisition order across call paths, check-then-act TOCTOU races around shared caches/files, and justify Atomic memory orderings.

Triggered only when reviewed files contain: unsafe , unsafe{, extern "C", MaybeUninit, transmute, from_raw_parts, or libc::.

  • Minimality & proof: Every unsafe block, unsafe fn, or unsafe impl Send/Sync must be as narrow as possible and carry an explicit // SAFETY: comment proving the invariant.
  • Pointer & slice soundness: Verify non-null, alignment, initialization, lifetime bounds, and absence of mutable aliasing (&mut T overlap) before from_raw_parts or raw pointer dereference.
  • FFI & descriptor hygiene: Check libc return codes (-1 / errno), prevent Rust panics from unwinding across FFI boundaries, and verify file-descriptor / allocation ownership transfer.

Triggered only when reviewed files contain: macro_rules!, proc_macro, proc_macro_attribute, or proc_macro_derive.

  • Single evaluation: Bind $x:expr arguments to a let once inside the macro expansion so caller side effects do not execute multiple times.
  • Hygiene & precedence: Prefix internal path references with $crate::, wrap re-emitted $t:tt fragments in parentheses, and emit syn::Error/compile_error! instead of panicking in proc macros.

Built-in Polyglot Playbooks + Project .aida/review-rules.toml Overrides:

  • Built-in playbooks cover rust (**/*.rs), cargo_toml (**/Cargo.toml), go (**/*.go), typescript_js (**/*.{ts,tsx,js,jsx,mjs,cjs}), python (**/*.py), c_cpp (**/*.{c,cc,cpp,cxx,h,hh,hpp,hxx}), java_kotlin (**/*.{java,kt,kts}), matlab (**/*.m), hdl_rtl (**/*.{v,vh,sv,svh,vhd,vhdl}), shell (**/*.sh), sql (**/*.sql), and config_data (**/*.{toml,yaml,yml,json}).
  • Projects can layer custom path rules in .aida/review-rules.toml with merge_builtin = true (appends to the built-in language playbook) or merge_builtin = false (replaces it).
  • Test companions are batched with their source: foo_test, test_foo, JUnit-style FooTest (including src/test/ mirroring src/main/), and HDL testbenches foo_tb or tb_foo.

Core CLI Commands

PR REVIEW, RANGE DIFF, FULL-FILE SCAN & VERIFICATION

aida review prepare 
# 1. Prepare a PR review (auto-resolves base..head & linked specs)
aida review prepare --pr 42 --write .aida/review-prepare-pr-42.md

# 2. Prepare a branch range or single commit review
aida review prepare --from main --specs STORY-3076
aida review prepare --commit HEAD --specs STORY-3076

aida review prepare --pr 42 \

07 / AGENT RUN, CHALLENGE & GATES

Running the Review: --run-review, --adversarial & Exit Codes

--run-review sends each batch to a review agent and anchors its findings. --adversarial has a second agent reproduce or refute each one. Review settings come from the merge base, never from the change under review.

Agent Run & Challenge

NEEDS --PR OR --FROM

--run-review 
# Finder + challenger, gate on high, publish SARIF and a PR comment
aida review prepare --pr 42 --run-review --adversarial \
  --effort high --challenger-effort medium \
  --fail-on high --sarif .aida/review.sarif \
  --write .aida/review-pr-42.md --post-comment

# Operator override of the challenger vendor
aida review prepare --pr 42 --run-review --adversarial \
  --challenger-agent codex
SettingResolution
Finder agent--agent, then AIDA_REVIEW_RUNNER_CMD, then [agents] vendor, then claude. The pick is printed on stderr.
Effort--effort, then AIDA_REVIEW_EFFORT, then default_effort, then the [agents] reviewer seat. claude: low to max; codex and custom runners: low to xhigh. Every source is validated.
Challenger effort--challenger-effort, then AIDA_REVIEW_CHALLENGER_EFFORT, then challenger_effort, then the challenger's seat.
Challenger agentAn installed vendor outside the change's [AI:<tool>] tags, preferring one other than the finder's. A same-vendor challenge is noted in the report. --challenger-agent is the operator's override.

Gates, Exit Codes & Output

REFUTED AND UNCHALLENGED FINDINGS STILL GATE

ExitMeaning
