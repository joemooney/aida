06 / ARCHITECTURAL RECOMMENDATIONS & EXECUTION ROADMAP

Four High-Impact Engineering Interventions

Concrete steps to preserve AIDA's high trunk integration cadence while reducing monolithic crate coupling, shrinking PR batch sizes below 400 LoC, and lowering post-merge rework.

ACTION 01 · WORKSPACE DECOMPOSITION

Split aida-cli-lib (675.6k LoC) into Bounded Domain Crates

78.3% of all Rust code (1,115 files) compiles inside a single library crate, and lib.rs was touched 216 times in the last 30 days (128,348 churn LoC).

  • Extract strict DAG crates: aida-orchestrator (drain/queue/leases), aida-forge (PR ship/review watch), aida-mailbox, aida-doctor, and aida-mcp-server.
  • Relocate the 240,863 LoC of dedicated Rust test files into domain-scoped integration targets so subcommand edits do not relink the entire workspace.
TARGET KPI: Reduce aida-cli-lib from 78.3% → <15% of Rust LoC; reduce incremental test link time (assumed benefit; not yet measured).
ACTION 02 · HUB & MEGA-FILE DECOUPLING

Shatter the 15 Mega-Files (>5k LoC) & Decouple models.rs

aida-core/src/models.rs has a cross-file fan-in of 1,003 files (69.7% of all Rust files), while handle_queue_command has a call fan-out of 790 outbound calls.

  • Partition models.rs (7,159 LoC) into narrow domain submodules (models::spec, models::queue, models::verdict, models::regen) and introduce narrow trait interfaces (expanding beyond the current 33 traits).
  • Enforce a CI file-size ratchet capping any single .rs file at 2,500 LoC (ratcheting to 1,500 LoC) and function call fan-out at <100 edges.
TARGET KPI: Eliminate all 15 files >5,000 LoC; cut models.rs direct file fan-in from 69.7% → <25%.
ACTION 03 · SMALL-BATCH PR RATCHET

Enforce a <400 Production-LoC Budget at Decomposition & Ship

31.6% of merged PRs since 2026-05-10 exceed the 400-LoC review threshold (40.1% in the trailing 60 days; 10.1% exceed 1,000 LoC), increasing reviewer context load and co-occurring with multi-round review cycles.

  • Separate Production Rust LoC from Test & Doc LoC in aida pr ship and aida review watch so test thoroughness is never penalized.
  • Cap net production code changes per PR at ≤300 LoC (advisor split gate at 400 production LoC or >8 production files) during /aida-decompose and queue pickup.
TARGET KPI: Shift PRs >400 LoC from 31.6% → <15% (illustrative target*); reduce median PR diff from 225 LoC → <180 LoC.
ACTION 04 · PRE-MERGE BLAST-RADIUS GATING

Wire CodeGraph Impact & Snapshot Isolation into Pre-Review Gates

cli_help_snapshot.txt alone generated 59,912 LoC of churn across 74 commits in 30 days. A hypothesis, not yet classified or measured, is that state-machine seams account for a large share of the 1,163 BUG- commits.

  • Shard monolithic golden help snapshots by subcommand so CLI flag additions do not conflict across concurrent worktrees.
  • Run automated codegraph impact checks on symbols with fan_in > 100 or fan_out > 100 prior to reviewer dispatch.
TARGET KPI: Reduce <21-day Rework Churn from 27.7% → <10% and BUG-/fix commit ratio from 31.6% → <15%.
