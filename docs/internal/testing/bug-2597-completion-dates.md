# Completion timestamp repair

<!-- trace:BUG-2597 | ai:codex -->

`aida db backfill-completed-at --dry-run` reports the number of missing stamps
that can be recovered from Completed status history and lists every unresolved
record. Omit `--dry-run` to persist those dates under the existing store writer
lock. Running it again changes no dates. The advisor runs this after merge;
the implementation lane must not run the live rewrite.

The cache projects `completed_at` from the stored stamp, falling back to the
latest Completed history timestamp. It projects `closed_at` for Rejected and
Superseded from their matching history. Schema version 17 triggers the normal
cache rebuild. Neither projection guesses dates from `modified_at`.

Read-only audit of a disposable copy of the current canonical objects on
2026-11-15: 5,333 stored Completed records, 980 missing stamps, and 42 recoverable
from history. A full rebuild using the new binary projects 7,823 records,
including 5,361 Completed rows. Of those, 966 retain NULL completion dates:
938 have no Completed history entry and 28 are derived epic rollups with no
persisted completion event. The cache's history fallback already recovers the
42 dates; the explicit backfill persists those dates into canonical objects.
No live data was rewritten. Counts include archived objects and are a snapshot,
so they can differ from an earlier cache audit. Every remaining NULL date is
listed below with its reason. The closure projection recovers dates for 595
of 1,306 Rejected records and 789 of 798 Superseded records; the rest lack their
matching terminal status-history entry and retain NULL closure dates.
