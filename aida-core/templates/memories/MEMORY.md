# AIDA Scaffolding-Pack Memory Index (master template)

- [feedback_aida_capture_proactive.md](feedback_aida_capture_proactive.md) — Run /aida-capture proactively; never let >5 commits land without backing reqs (lesson from 2026-05-04 backfill)
- [feedback_dialog_role_responsibilities.md](feedback_dialog_role_responsibilities.md) — The **advisor** role is the project's persistent strategic + tactical partner (`dialog` is a deprecated alias for it). 6 responsibilities: route work, capture friction as filings, articulate mental models, detect strategic gaps, garden queue, curate memory. NOT a code-implementer.
- [feedback_claude_code_statusline_posix.md](feedback_claude_code_statusline_posix.md) — Claude Code runs statusLine and unmarked hooks under /bin/sh (dash on Ubuntu); bashisms silently fail to empty
- [feedback_no_partial_force_overwrite.md](feedback_no_partial_force_overwrite.md) — Never run bulk --force when asked for a subset; filtering output ≠ scoping the command (paradox CLAUDE.md/settings.json clobber, 2026-05-04)
- [feedback_local_time.md](feedback_local_time.md) — Display timestamps in user's local timezone for CLI/status/version; keep UTC only on disk
- [feedback_no_eval_role_enter.md](feedback_no_eval_role_enter.md) — Don't wrap auto-evaled aida subcommands (role enter/end/add, dev activate/deactivate) in `eval "$(...)"` — shell function auto-evals them; the wrap double-evals and breaks
- [feedback_capture_doc_seeds.md](feedback_capture_doc_seeds.md) — Capture doc seeds proactively as `aida comment add` on relevant reqs during work — every design/UX/comparison discussion. EPIC-24 will eventually automate; until then, manual.
- [feedback_fetch_before_commit.md](feedback_fetch_before_commit.md) — On long-running sessions, `git fetch` before staging commits to avoid divergent-branches surprise at push time
- [feedback_failed_flag_attempts_are_ux_signals.md](feedback_failed_flag_attempts_are_ux_signals.md) — Agent flag-attempt errors are diagnostic UX signals; default to filing them, don't frame as "if that bothers you"
- [feedback_verify_before_filing.md](feedback_verify_before_filing.md) — Before filing TASK/STORY based on user friction, verify the symptom's actual cause via diagnostic commands; the friction may be timing/visibility, not a missing capability
- [feedback_goal_prompt_phrasing.md](feedback_goal_prompt_phrasing.md) — /goal prompts: use only real command flags (no `--next` shorthand) AND pick mechanism clauses that route handoffs as intended (autonomous-merge skips reviewer queue)
- [feedback_pause_for_design_input.md](feedback_pause_for_design_input.md) — On UX/design-laden pickups, present concrete design forks (AskUserQuestion + previews) before implementing; ship minimal, file the vision as a follow-up TASK
- [feedback_check_in_flight_before_rejecting.md](feedback_check_in_flight_before_rejecting.md) — Before rejecting/pivoting a spec, check `aida session leases` for active work on it. Implementer can ship rejected-spec code in good faith otherwise.
- [feedback_trust_reviewer_over_dialog_intuition.md](feedback_trust_reviewer_over_dialog_intuition.md) — When reviewer verdict conflicts with advisor-role recommendation on merge: trust the reviewer. Advisor reads commit messages; reviewer reads code.
- [feedback_run_help_before_suggesting_flags.md](feedback_run_help_before_suggesting_flags.md) — Run `<cmd> --help` before suggesting CLI flags. Don't pattern-match from mental models — verify the actual surface.
- [feedback_precise_lifecycle_vocabulary.md](feedback_precise_lifecycle_vocabulary.md) — Don't conflate committed / pushed / PR-opened / merged / completed / released under fuzzy "ship". Use the precise verb per state.
- [feedback_parallel_vs_sequential_ui.md](feedback_parallel_vs_sequential_ui.md) — "Next steps" UI splits into parallel choices (pick ONE — table) vs sequential steps (do ALL — numbered list). Different shapes, different formats.
- [feedback_propagate_generic_discipline_via_scaffolding.md](feedback_propagate_generic_discipline_via_scaffolding.md) — When writing a generic-applicable memory, ALSO consider scaffolding propagation (docs/aida/discipline, starter memory pack, CLAUDE.md template). AIDA-specific & user-personal memories stay local.
- [feedback_refinements_must_be_acceptance_criteria.md](feedback_refinements_must_be_acceptance_criteria.md) — Design refinements on a filed spec must edit acceptance criteria (or file a follow-up TASK). Comments are NOT binding on implementers; they correctly follow the original spec.
- [feedback_competitive_analysis_is_living_doc.md](feedback_competitive_analysis_is_living_doc.md) — Competitive landscape moves fast; maintain `docs/competitive-analysis/` with refresh cadence + dated snapshots. NOT a one-shot exercise.
- [feedback_self_test_via_dogfood_merge.md](feedback_self_test_via_dogfood_merge.md) — When fixing infrastructure (orchestrator, auto-bump, etc.), ship via the system being fixed — the merge exercises the new code path. Strongest possible validation.
- [feedback_pushback_on_overengineering.md](feedback_pushback_on_overengineering.md) — Advisor balances friction-to-spec (capture) with scope-to-MVP (push back). EPIC-shaped ideas need smallest-valuable-slice + revisit-trigger before filing; daemon-grade infrastructure when a bash loop would do is yak shaving.
- [feedback_three_mode_autonomy_taxonomy.md](feedback_three_mode_autonomy_taxonomy.md) — Autonomy has two orthogonal axes (human present? what to ask?); three modes default/--zen/--no-human map human-role to pause-behavior; classify prompts by kind.
- [feedback_check_orchestrator_before_manual_steps.md](feedback_check_orchestrator_before_manual_steps.md) — Before instructing manual review/merge/run-command steps on a spec, verify no live --auto-complete orchestrator is driving it (it runs phases 3-6 itself); always state execution context.
- [feedback_finish_checkpoint_clarity.md](feedback_finish_checkpoint_clarity.md) — Implementer finish-checkpoints must include state, deciding factor, recommendation+rationale, per-option downstream consequences, an explicit `advise` escape, and decoupled coupled-decisions (push/PR vs followup-filing).
- [feedback_capture_over_concentration.md](feedback_capture_over_concentration.md) — File observations the moment you identify them; backlog (approved + low-priority + un-queued) is the right captured state for non-urgent. Refusing to file loses the observation. Over-engineering caution applies to build, not capture.
- [feedback_explicit_paste_ready_prompts.md](feedback_explicit_paste_ready_prompts.md) — Mark the boundary: text the user pastes to an agent (or runs themselves) goes in a labelled, set-apart block ("Paste to the implementer:" / `code fence`); advisor-to-user framing stays as prose around it. Don't make the user ask *"is that what I tell the agent?"*.
- [feedback_memory_pack_hygiene.md](feedback_memory_pack_hygiene.md) — Memories can become OBE (capability landed, empirical claim contradicted, dependency drift, duplicate/superseded, project pivoted). Run an explicit audit cycle on triggers (keystone ship, release, N-week stale). Six per-memory + three pack-level self-reflection questions; three outcomes (retire / revise / preserve).
- [feedback_question_existing_form_not_just_existence.md](feedback_question_existing_form_not_just_existence.md) — When surfacing prior art to the user, BOTH name it AND question whether its current implementation form still aligns with stated principles. Path-dependence (bash got there first, filesystem worked so we stuck with it) ≠ correctness. Don't stop at "you have it"; ask "is it in the right shape?"
- [feedback_no_unsolicited_stop_framing.md](feedback_no_unsolicited_stop_framing.md) — Don't append unsolicited "consider stopping / sleeping / morning-fresh" framings to recommendations. User differentiates context themselves (low-risk drain when away vs high-priority at-keyboard); advisor's wellness commentary is a distraction. Only legitimate exception: confirmation prompts on destructive actions.
- [feedback_reliability_fixes_use_keyboard_not_drain.md](feedback_reliability_fixes_use_keyboard_not_drain.md) — Reliability fixes for the autonomy keystone itself (orchestrator lease management, reviewer/implementer skill enforcement, phase-X recovery) ship best at the keyboard via `--zen --auto-complete` with the advisor watching, NOT unsupervised headless drain. The fix rides through the broken system; if the broken system's failure rate is non-trivial, the fix gets caught in it. Refines feedback_self_test_via_dogfood_merge for the recursive-failure-risk case.
- [feedback_one_master_advisor_until_subsystems.md](feedback_one_master_advisor_until_subsystems.md) — Multi-agent AIDA projects have ONE master advisor (live advisor-role session) until subsystem-scoped advisors exist (SPIKE-10). Sibling agents capture observations + ship bounded acceptance work autonomously; architecture-impacting changes (file formats, MCP contracts, orchestrator behavior, EPIC-shaped work, convention changes, memory pack edits) require master sign-off BEFORE the PR opens, not at review time. As subsystems emerge, master delegates per-subsystem.
- [feedback_sibling_agents_stop_and_flag.md](feedback_sibling_agents_stop_and_flag.md) — When a sibling agent finishes its bounded work AND finds the worktree contains unrelated dirty state from other agents/sessions, the correct discipline is STOP and flag — do NOT co-mingle bounded work with accumulated noise in a single PR. Flag the state + recommend isolation; the master (or another session) handles the worktree-add + patch-apply isolation. Preserves separation of authorship in multi-agent projects.
- [feedback_sketch_first_pays_for_itself.md](feedback_sketch_first_pays_for_itself.md) — Architecture-class sketch-first sign-off (sibling agent writes a sketch comment; master approves/revises/declines before implementation) is empirically cheaper than implement-then-revise loops. Codex's BUG-328 sketch (2026-05-22) caught 3 substantive issues (Draft ambiguity, adjacent review-story exception, parallel scanner paths) that would have been post-merge cleanup PRs. When to invoke + when not.
- [feedback_headless_advisor_is_cold_boot.md](feedback_headless_advisor_is_cold_boot.md) — The --no-human headless advisor is a fresh `claude -p` per punt, NOT the running advisor session; same model, different context. No-daemon simplicity is a virtue to preserve, not a limitation. Three trajectories close the gap: (1) substrate enrichment — every memory write is training data; (2) fork-from-live-session via JSONL copy + `--resume` (SPIKE-11); (3) persistent advisor entity (SPIKE-10 / MCP-bus) — heavier ops, explore (2) first.
- [feedback_advocate_not_be_passive.md](feedback_advocate_not_be_passive.md) — Advisor shifts from capture-only to advocacy: proactively raise strategic concerns, push back on drift, name wedge-vs-pile work, treat substrate as load-bearing artifact, treat partnership as the unit. License granted explicitly by the user.
- [feedback_dated_artifacts_immutable.md](feedback_dated_artifacts_immutable.md) — Cross-cutting refactors update living guidance + code; leave dated SPIKE outputs, PROMPT_HISTORY entries, competitive-analysis snapshots, spec comments, and commit messages frozen at time T (BUG-116 origin).
- [feedback_aida_executable_direct.md](feedback_aida_executable_direct.md) — Use the global `aida` executable directly instead of `cargo run -p aida-cli` for routine commands to avoid build latency.
